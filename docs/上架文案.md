## 一句话简介（表单里的短描述）

在 DeepSeek Harness（DSH 桌面版）和 WorkBuddy 之间双向搬运对话记录，支持跳过归档会话、写会话索引、日志合法性校验。

## 详细说明

### 它解决什么问题

DSH 和 WorkBuddy 各存一套会话格式：DSH 用多帧 zstd 的 `session.v4.jsonl.zstd`，WorkBuddy 用单文件 JSONL + SQLite 索引，两边都没有「导入/导出对话」的入口。想换工具，历史对话就断在那里。

这个技能把两边的格式、索引、注册表都打通，一条命令搬一条会话。

### 主要能力

- **DSH → WorkBuddy**：批量导入，自动识别并跳过已归档会话（DSH 只归档不删除，目录里混着归档的），写入 `workbuddy.db` 的 `sessions` 表
- **WorkBuddy → DSH**：导出单条会话，自动挂到对应工作区、退出归档名单，交给 DSH 自己重建投影缓存
- **体检**：`verify.js` 复刻了 DSH 读取器的硬约束（surfaceOp、消息形状、工具生命周期、turn/step 配对等），写完自动校验，不合格不落盘
- **防覆盖**：两个方向遇到同 id 都跳过并提示，要覆盖用 `--overwrite`、要另存用 `--new-id`

### 实现要点（对技术用户）

- DSH 的 zstd 是**多帧**的，Node 的 `zstdDecompressSync` 只解第一帧（只能拿到 203 字节的会话头）——按 magic `28 B5 2F FD` 切帧逐帧解
- 归档名单在 `~/.dsh/storages/workspace.json` 的 `global.archivedSessionIds`
- 不伪造 DSH 的 `session_projcache`：官方文档写明缺失/过期记录会被当作不存在、由日志重建
- 导出事件严格按 DSH 的 fold 规则排序，否则打开会报 `SessionFormatError`

## 使用示例（表单里的「怎么用」）

1. 「把 DSH 桌面版的对话导入到 WorkBuddy」
2. 「把这个 WorkBuddy 会话导出到 DSH，工作区是 D:/MyProject」
3. 「DSH 里打开导入的会话报 SessionFormatError，帮我查一下」

## 运行要求

- Node ≥ 22.15（zlib zstd）
- Python 3（仅标准库 sqlite3）
- 本机安装 DSH 和 WorkBuddy；目前仅在 Windows 验证

## 权限说明（审核可能会问）

- 会读写 `~/.workbuddy/workbuddy.db` 与 `~/.dsh/storages/workspace.json`——应用只认自己的索引表/注册表，不写索引，搬过去的会话不会出现在列表里。脚本改前自动备份 `*.bak-<时间>`。
- 不联网、不读密钥、无遥测，全部本地文件操作。
